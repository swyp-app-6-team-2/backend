## 📌 작업 내용

사용자가 재료명을 직접 입력하여 본인 전용 보유 재료로 등록하는 기능을 구현합니다.
등록된 커스텀 재료를 내 재료 목록과 재료 기반 추천에 반영하고, 회원탈퇴 시 함께 삭제합니다.

## 📝 상세 내용

### 등록 API

- POST /api/v1/users/me/ingredients/custom
- Access Token 인증 필수
- 요청: { "name": "루꼴라" }
- 요청 하나당 재료 하나를 생성하고 즉시 본인의 보유 목록에 반영합니다.
- 카테고리와 이미지는 입력받지 않습니다.
- 재료명은 앞뒤 공백 제거 후 1~50자로 제한합니다.

### 저장 정책

- user_custom_ingredient 테이블에 사용자 ID, 재료명, 생성 시각을 저장합니다.
- 사용자 본인에게만 표시하며 공통 재료 마스터에는 추가하지 않습니다.
- 마스터 또는 기존 커스텀 재료와 이름이 같아도 새 항목으로 등록합니다.
- 이름 중복 방지와 기존 마스터 자동 연결은 이번 범위에서 제외합니다.

### 조회 및 추천

- 기존 내 재료 목록의 data.ingredients 배열에 함께 반환합니다.
- ingredientType과 customIngredientId를 추가합니다.
- 커스텀 재료의 ingredientId, categoryCode, iconUrl은 null로 반환합니다.
- 프런트는 직접 추가한 재료 영역과 기본 아이콘으로 표시합니다.
- 검색은 기존 재료와 커스텀 재료 이름 모두에 적용합니다.
- 기존 마스터 ID 매칭을 유지하고, 커스텀 재료는 recipe_ingredient.name과
  양쪽 앞뒤 공백 제거 후 완전 일치로 매칭합니다.
- 조건이 하나 이상 일치하는 본인 레시피를 추천 후보로 포함합니다.
- 중복 재료로 동일 레시피의 추천 확률이 높아지지 않도록 처리합니다.

### 탈퇴 및 요청 처리

- 회원탈퇴 시 커스텀 재료를 함께 삭제합니다.
- 등록 시 사용자 잠금과 탈퇴 상태 검사를 적용합니다.
- 동일 등록 요청을 재전송하면 새 항목이 생성됩니다.
  프런트는 요청 중 중복 터치와 자동 재전송을 방지합니다.

### 구현 범위

- 기존 UserController와 UserService에 등록 기능을 추가합니다.
- 요청·응답 DTO는 분리합니다.
- 커스텀 재료 수정·개별 삭제 API, 중복 방지, 동의어 매칭은 제외합니다.
